# 第21份补充：辅助合计最多占主Loss的10%

用户要求降低辅助Loss强度，本次按“**加权辅助合计 ≤ 0.1 × 主Loss**”执行，同时限制每项系数≤0.1。旧权重1实验保留，只作历史强辅助对照。

## 具体公式

主Loss `J = BCE(gamma*stay,y)`，与原模型完全一致；左辅助 `N`仍是按会话归一化的离散停止NLL，右辅助 `C = BCE(stay,y)`仍按请求平均。每个开启项的初始系数为0.1：

```text
A = a*N + b*C                  a,b ∈ {0,0.1}
c = min(1, 0.1*J.detach()/max(A.detach(), tiny))
Loss = J + c*A
```

因此每步`c*A/J≤0.1`，而不是让两个分支各占主Loss10%、合计达到20%。`c`是无梯度的当前训练batch尺度调节系数，主Loss梯度系数保持1；辅助梯度仍乘以实际有效系数`a*c`、`b*c`。不把系数的计算也放进反传，避免`A/A`使辅助梯度抵消。仅使用train当前batch，无valid/test信息。

**Loss数值上限不是梯度范数上限**：同样数值的损失也可能有不同梯度。真实训练将逐batch存储主Loss、原始辅助项、缩放系数、有效权重及最终占比，断言每步满足要求。专项测试核对缩放前后梯度的参考公式。

左NLL仍按每场一次计算：终屏标签`L=req_idx_raw`不进入网络；训练请求/会话比15.742676用于与物理shuffle batch配合。与上一轮保持相同归一化，不另换数据目标。动态缩放后最终左辅助权重依batch变化，因此不能把整轮加权项简单称为固定系数的全局NLL均值。

## 实验协议

沿用KR v3：train 2022-04-08至05-06，1,721,745请求/109,368场；valid 05-07为57,872请求/3,822场；test 05-08为48,898请求/3,281场、855用户。54字段、schema、物理请求顺序、屏末pace、两塔独立Omni均不改；编码UID置0，raw UID仍用于User-AUC。

单威布尔+pace、混合威布尔+pace；每种仅左、仅右、双辅助，seeds2026/2027/2028，共18条新轨迹。旧无辅助以及旧权重1结果直接复用。5个连续epoch，每轮421步、最终2105步；每轮末完整valid/test，固定第5轮停止、不回滚best，不以test调权。

同seed全参数初始化hash、优化器分组、输入顺序与无辅助旧对照核对。AdamW预算lr=.005、内容lr=.001，普通矩阵decay=1e-6，embedding/bias/1D为0；batch4096、clip10、CPU4线程，无scheduler/EMA/冻结。新类只改变Loss系数，不新增参数、不改变forward。
