## 2. 数学公式及联合反传

新增11项测试，与既有65项合计**76项通过**。其中：

- 六配置新旧模型的完整state_dict、前向、loss、各参数梯度与一次AdamW更新逐值一致，包含梯度为None的非活跃路径。
- 混合威布尔用独立NumPy计算`S_mix(t+1)/S_mix(t)`；非均匀先验、原点、大屏数及截断边界均有案例，额外用有限差分gradcheck核对参数梯度。
- 真实train首批数据中，乘积公式误差为0，独立NumPy的gamma最大绝对误差约`6.48e-8`。logS最大绝对误差约`3.47e-5`，使用`atol=2e-6, rtol=2e-6`的相对/绝对容差检查；生产参数先以float32转换尺度/shape再提升到float64，独立参考直接用float64，不能要求两者逐位相等。
- step_only分钟head梯度为0；屏数head、内容head、两塔用户Embedding都有梯度和真实更新，pace新增列也有梯度。单一乘积BCE同时驱动两塔，没有detach、冻结、预热或辅助loss。

## 3. 一次连续训练的短程重放

使用真实train前8192条，每轮2个batch，连续3轮，共6次更新。短程valid仅取4096条，test不参与训练或选择。AdamW预算LR=.005、内容LR=.001，矩阵decay=1e-6、Embedding/bias/一维零decay；batch4096、无累积、CPU4线程，与原实验协议一致。

新`JointExitTrainer`和原`BudgetTrainer`分别从同seed开始，在同一数据上重放，以下全部逐值一致：

- 每一次更新的loss和完整参数状态哈希。
- 最终AdamW的step、一阶矩、二阶矩。
- 所有valid节点及选出的checkpoint。
- 1轮和3轮预算快照，优化器step分别为2和6。
- 首步梯度及真实参数更新记录。

短程验证节点为`0,1,2,3,4,5,6`，因为2batch下25%与50%节点重合。它验证训练生命周期及状态连续性，不作为新AUC结论，也没有代替原421步/轮的全量训练。

读取第13份`2026/mixture_step_pace`的3epoch预算checkpoint，选择step=1263。核对它确为预算范围内最低完整valid LogLoss，而非根据test挑选。

## 5. 亲自debug

在仓库根目录运行：

```bash
uv run python workspace/kr_time_budget/debug_current_run.py --stop-at views
uv run python workspace/kr_time_budget/debug_current_run.py --stop-at forward
uv run python workspace/kr_time_budget/debug_current_run.py --stop-at checkpoint
```

PyCharm可直接运行该文件，在`diagnose()`里依次看`batch`、`views`、`forward`、`trace`、`training`、`saved`。单步进入`KRExitModel.components()`可看两塔概率和乘积；进入`mixture_parts()`可看scale、shape、prior、posterior、log_mix_s和gamma。`checkpoint`断点位于重载后，局部`model/checkpoint/best`对应已有正式run。

默认每次新建`runs/diagnostics/<时间戳>/`，日志自动保存；无需手工重定向。首批样例分别导出到`initial_trace.parquet`和`checkpoint_trace.parquet`。历史`debug_time_budget.py`仍是v7入口，勿混淆。

## 结论边界

本轮支持“提炼后的模型/Trainer与原实现，在六配置单步与一个配置短程/完整推理上等价”。没有重跑全部18条正式训练轨迹，也没有给新`run_exit_experiment.py`另跑全量训练；其验证目前为语法、CLI导入和所用模型/Trainer的上述检查。
