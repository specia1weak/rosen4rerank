结论：赞成方向A。保留6.1现有继续概率模型；当屏价值由独立的W监督学习，未来价值由M学习，不再要求右塔stay代表内容满意度。第16份负结果保留，不通过反转分数或辅助损失来改写它。

但“方向成立”与“现有模型已满足下游所有要求”是两件事。第18份对在线时间边界的提醒正确，尚需补充分屏边界；对内容隔离、单调性、校准及统计显著性的部分表述也需要收窄。

本次只读审阅计划、源码和已有报告，并对完整test做一次分屏统计。没有训练、修改模型、重建数据或重跑预测。仓库内未找到计划所引的`V6-refine-simplied.pdf`，因此下述数学核对针对计划转述的公式，不能确认PDF原文与页码。

## 1. 可以接受的方向

若w_t是当屏观看时长，F_t是当屏之后的总观看时长，并定义没有下一屏时F_t=0，则：

\[
E[w_t+F_t\mid s,a]
=W(s,a)+P(y_t=1\mid s,a)M(s,a),
\]

其中：

- W(s,a)=E[w_t|s,a]，用所有合格请求的当屏时长监督。
- M(s,a)=E[F_t|s,a,y_t=1]，是继续条件下的未来总时长；若直接用所有请求的未来时长训练M，再乘继续概率，会重复计入停止的零值。
- 继续概率使用gamma×stay，不要求这两个因子单独被识别。

这一分解不要求stay与当屏时长正相关，因此第16份回测不构成放弃方向A的理由。但只把乘积校准好仍不够：W、M的目标、条件、时长单位和决策时刻也要一致。

离线日志中对已曝光列表的预测成立，不自动证明换一个候选列表后的反事实价值或线上收益；恒等式本身不解决行为策略覆盖和选择偏差。

## 3. 第18份：S和权重能说明什么

当前主线的预算参数网络只读30个共享背景字段及4个预算先验，不直接读当前列表和本场内容反馈；两套Embedding独立。这是可验证的输入和参数路由。

但预算网络仍由最终乘积BCE训练，梯度取决于另一塔输出及y_continue。不能据此声称它学到了“不被内容污染”的真实外生预算，或者S已精确补偿了后段样本稀疏。共享背景和历史预算也可能与内容偏好相关。

当前有效时钟是屏数r=req_idx−1，分钟分支恒为1。因此应记作S_step(r|U,C,预算先验)，不能直接称作已验证的分钟预算S_time(e)。观测到log S与累计分钟相关，不能把屏数分布变成分钟分布。

现有诊断中S在45,617对相邻屏上上升0次，支持当前输出不增；浮点下溢、截断和权重封顶可能产生平台。kappa=min(exp(−log S),kappa_max)应表述为非递减、带上限的预算分支状态权重，不能承诺每一步严格增加。实现时应先在log域封顶再指数化。

对于固定状态s，正的状态权重kappa(s)在无限容量、逐状态可独立优化时不改变该状态内损失的最优解；共享有限参数网络会受状态间权衡影响，最优参数可能改变。因而这可以作为训练重加权的动机，效果仍须与kappa=1对照。当前尚未做Generator训练，不能宣称下游已获益。

## 4. 时间边界：不只pace

当前6.1离线任务是在重建屏结束后预测还有没有下一屏。下游候选列表打分发生在屏开始之前，不能直接把二者输入接口等同。

| 数据或字段 | 当前实现 | 对下游的含义 |
| --- | --- | --- |
| elapsed_min / pace | 当前屏最后一次曝光时间加其play_clip，再减会话起点；pace=log1p(elapsed_min/req_idx) | 含当前屏实现后的信息。未曝光候选列表打分时不可用，不能仅在推理时替换成屏前值而声称沿用同一验证结果。 |
| 预算时钟 | 现有mixture_step只用req_idx−1 | 不含当前屏耗时，但屏号定义仍依赖下面的离线分屏规则。 |
| prev1 / sess_cum / hist_tags | 只取前序重建屏及头部余数历史 | 相对于既定离线切块没有读取当屏反馈；分屏变更后仍须重算。 |
| slate静态属性及过去日物品先验 | 从实际连续消费的6个视频汇总 | 对明确给定的6项候选列表可计算对应字段，但现有日志并不证明6条视频当时是一起下发的真实请求。 |
| 分屏起点 | `(event_idx − session_n % 6) // 6 + 1` | 起点依赖整场最终事件数，无法由会话前缀确定；去掉pace不能消除这一差别。 |

分屏反例：同样的前6条事件，如果整场最终有12条，前6条组成第1屏；如果最终有13条，第1条成为头部余数，第2–7条才组成第1屏。屏边界、历史及编号由未来的整场长度决定。

本次通过Polars直接扫描`data/v3/test.parquet`和`events.parquet`，完整test为48,898请求、3,281场；其中2,702场有头部余数，共7,944条头部余数事件。[统计记录](../../runs/plan18_review/boundary_audit.json)和[日志](../../runs/plan18_review/logs/review.log)。该计数不是AUC评估，未涉及训练或模型输出。

这不抹去现有固定离线协议下的模型比较，但限制了把这些结果直接当作在线候选打分证据。历史run保留原口径；若建立屏前数据，另存新版本并重新评估相应模型。

## 5. 后续建议

先固定下游实验口径，再写W、M与Generator。

1. 若继续做离线重建屏上的方法验证，可以复用v3和现有预测，明确这是离线分析，不能当作已可在线部署的系统。
2. 若目标是屏前候选列表打分，建立独立的前向分屏数据版本：从已知起点按6项前向切块，明确最后不足6项的处理和可变长度掩码；保留屏开始、屏结束两个时钟，历史严格只取屏前。该重建屏仍是代理请求，不冒充原始真实请求。
3. 第一版屏前继续模型可从无pace的mixture_step开始；若要加历史pace，使用可观测前序屏数作分母，并定义首屏无历史时的值。训练和推理使用同一定义，重新报告完整valid/test结果，不能沿用旧pace模型指标。
4. 为W和M明确同一时长口径。M的目标是继续条件下的屏后未来时长；W目标是当屏时长。未来标签只作监督，不进入屏前特征。沿用整场时间切分，使用训练集拟合编码，先建立未加kappa的基线。
5. 随后再比较Generator的kappa=1与预算权重；继续记录截断比例、有效样本量和下游效果，不称其为无偏估计。

本轮结论是支持方向A并补全接口条件；不是声称W/M已搭建或下游实验已通过。已有6.1训练口径：KR v3，train截至2022-05-06共1,721,745条，valid为05-07共57,872条，test为05-08共48,898条；6配置×3seed连续3epoch，分别在1/3epoch预算内按完整valid LogLoss选点，36组完整test评估。原日志在[plan13 train.log](../../runs/plan13_ablation/logs/train.log)，组件只读回测日志在[plan16 run.log](../../runs/plan16_component_backtest_checked/logs/run.log)。
