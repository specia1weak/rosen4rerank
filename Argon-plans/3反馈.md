这套代码整体工程质量很高（特别是 `mixture_survival` 在 log 域用 `logsumexp` 和先减后 `exp` 防下溢、以及 `README.md` 里发现 `-req_idx` 在单场内 `Session-GAUC = 1.0` 的陷阱）。

但仔细核对 `time_budget.py` 的前向逻辑和 `README.md` 的数据规则后，里面藏了 **4 个实质性的模型/数据 Bug**。如果不改直接跑，你的 `Ours` 模型大概率会训崩，或者在测试集上跑不赢 `Fusion`。

按严重程度从高到低排列如下：

---

### 1. 致命数据 Bug：`GroupKFold` 按用户切分，却给测试用户填“全局常数先验”

看 `README.md`「数据与边界」里的这两条规则：

* *“用户场均预算只用训练用户、此前已完成会话……**测试用户使用这些训练场的总体先验**。”*


* *“`GroupKFold(5)` 按用户分组，所有会话跟随用户，无训练/测试用户交集。”*



**问题在哪：**
因为你用的是按 `user_id` 分组的 `GroupKFold`，**测试折（Test Fold）里的每一个用户都是“测试用户”（不在训练用户集合里）**。如果代码只给训练用户算历史场均时长 `user_hist_session_s`，而给测试用户统一填训练集的全局均值，就会发生灾难性的**训练/测试分布失配（Covariate Shift）**：

* **训练时**：每个用户有自己真实的历史场均时长（区分他是 2 分钟碎片用户还是 30 分钟重度用户），模型会高度依赖这个特征去预测威布尔的尺度参数 $\lambda$；
* **测试时**：测试折里 100% 样本的这项特征突然变成了**同一个全局常数**，相当于测试时直接废掉了用户预算先验 $g$！

**怎么改：**
用户在**当前日期之前**已经结束的历史会话（`prior_available_date < current_date`）属于已知历史日志，根本不是未来信息泄漏。无论是训练折还是测试折的用户，都应该用**该用户自己在当前日期之前的历史已完成会话**去算滚动场均时长（再统一用训练集的全局均值做贝叶斯平滑兜底冷启动）。

### 2. 致命机制 Bug：两阶段切换时的“0.5 梯度休克”与共享编码器漂移

看 `time_budget.py` 的 `predict` 函数和 `README.md` 的训练策略：

```python
gamma, _, _ = mixture_survival(self.budget_net(x), b['elapsed_minutes'], b['delta_minutes'])
if self.mode == 'budget' or self.stage == 1:
    return gamma
return gamma * torch.sigmoid(self.content_net(x).squeeze(-1))

```

* **前 3 个 Epoch（`stage == 1`）**：只训 `gamma` 拟合 `y_continue`（均值为 $0.80$ 左右），此时 `self.content_net` 完全不参与计算，处于**随机初始化状态**。


* **第 4 个 Epoch 第 1 步（切到 `stage == 2`）**：预测公式突然变成 `gamma * sigmoid(content_net(x))`。因为 `content_net` 是随机初始化的，它的初始输出 `sigmoid(0)` 约等于 **$0.5$**！


* **后果（梯度休克）**：在 Epoch 3 结束时模型预测值还是正常的 $0.80$，一进 Epoch 4 预测值瞬间腰斩变成 $0.80 \times 0.5 = 0.40$！这会在 Epoch 4 开头产生巨大的伪 BCE 梯度，而此时**底层的共享编码器（`omni_embedding`, `slate_attention`, `history_attention`）依然保持着 `1e-3` 的高学习率**（只有 `budget_net` 被降到了 `1e-4`）。结果就是共享 Embedding 被这股冲击波瞬间冲歪，连带把 `budget_net` 的输入空间 `x` 也毁了（`README.md` 自己也承认了：*“共享编码器也继续学习，因此不能声称整条预算路径已冻结”*）。



**怎么改：**

1. **消除切换休克**：在初始化 `self.content_net` 的最后一层 `nn.Linear(32, 1)` 时，把它的 `bias` 初始化为 $+2.0$（或训练集留存率对应的 logit），或者在 `stage == 2` 开启瞬间先冻结底层共享编码器 1 个 Epoch 让 `content_net` 适应。
2. **真正锁住预算塔输入**：在 `stage == 2` 时，喂给 `budget_net` 的特征改为 `self.budget_net(x.detach())`，防止 `content_net` 更新共享 Embedding 时把预算生存曲线带偏。

### 3. 生存函数退化 Bug：`budget_net` 把当前时间 $e_t$ 当作了参数网络输入

看 `time_budget.py` 第 61 行：

```python
x = self.encode(b)
gamma, survival, log_survival = mixture_survival(self.budget_net(x), b['elapsed_minutes'], b['delta_minutes'])

```

在 `'ours'` 模式下，`x` 包含了全特征 `B1 + B2 + B3 + B4`。这意味着 `B2` 里的 **`elapsed_minutes`（当前已消耗时间 $e_t$）和 `req_idx`（当前第几屏）既被送进了 `budget_net(x)` 去预测威布尔参数 $(\pi, \lambda, z)$，又作为自变量 `elapsed` 送进了 `mixture_survival**`！

**后果：**

1. 威布尔分布之所以能保证累计生存率 $S(e)$ 单调递减，前提是同一个会话状态下尺度 $\lambda$ 和形状 $z$ 对时间 $e$ 是常数，时间只通过 $(e / \lambda)^z$ 起作用。如果 $\lambda(e_t)$ 本身就是 $e_t$ 的神经网络函数，那么 $(e_t / \lambda(e_t))^{z(e_t)}$ 就退化成了一个毫无单调约束的普通黑盒 MLP！这也是为什么 ChatGPT 在 `README.md` 末尾警告你：*“预算参数随当前 X_all 变化，$S(e_t\vert{}X_t)$ 不构成固定会话预算的统一累计生存曲线”*。


2. 更糟的是，在 `stage == 1`（前 3 个 Epoch），`budget_net(x)` 同时看到了当屏内容 `B4`（`slate`）和历史反馈 `B3`。它会在前 3 个 Epoch 直接把“内容好坏”也学进 $\lambda(x)$ 里，导致 `gamma` 根本不是纯时间预算，到了 `stage == 2` 就没有残差留给 `content_net` 学了！



**怎么改（同时严格满足 Leader“两塔输入特征集相同”的要求）：**

* 既然 Leader 要求两塔输入特征集相同，注意 **`mixture_survival` 本身就是预算塔的一部分**——它已经显式接收了 `B2` 的时间特征 `elapsed_minutes`！


* 因此，在送入 `budget_net` 预测分布参数 $(\pi, \lambda, z)$ 之前，应该把 `x` 中的会话内时钟 `B2`（甚至在 `stage == 1` 预热时的当屏特征 `B4`）掩码置零，让 $(\pi, \lambda, z)$ 只由会话先验决定，而时间进程 $e_t$ 严格只从生存公式的自变量 `elapsed` 入口进入。这样整座预算塔吃的特征集没变，但算出来的 $S(e_t)$ 就是一条真正合法的累计生存曲线！

### 4. 物理口径 Bug：拿当屏 6 个视频的“物理总片长”当作生存步长 `delta_minutes`

看 `README.md` 的说明：

* *“模型时钟：当前列表第一条记录时间减本场第一条记录时间。文档末尾提出的‘当前屏末条时间+播放时长’保留在 `elapsed_end_s_DIAGNOSTIC`，不作为输入。”*


* *“列表总片长还作为生存公式的 `delta`”*。



**问题在哪：**

1. 它违背了你们 Leader 刚刚定下的口径（`elapsed_end_s` 才是 Leader 说的“首尾时间戳相减 + 最后一个视频播放时长”的挂钟时间，ChatGPT 却把它扔进 `_DIAGNOSTIC` 不用，改成了第一条记录的时间）。


2. 更严重的是：它把当屏 6 个视频的物理片长之和（`slate_dur_sum_s`）直接当成了生存公式 $\gamma(e_t) = S(e_t + \Delta_t)/S(e_t)$ 里的 $\Delta_t$！
我们在上一轮看过 KR 的数据统计：视频物理片长 `duration_ms` 动辄几分钟甚至十分钟（截断上限是单视频 600 秒 = 10 分钟），但用户遇到不喜欢的长视频其实 **3 秒钟就划走了**！
如果你把 6 个视频的物理片长之和当作 $\Delta_t$ 代入威布尔公式，一旦当前屏抽到了两个 5 分钟的长视频，$\Delta_t$ 就会暴涨到 10 分钟以上，导致威布尔公式误以为“用户要花 10 分钟才能看完这一屏”，从而强行压低 $\gamma_t$ 预测用户必退！这会把“视频片长”和“时间预算耗尽”严重混杂。



**怎么改：**

1. 把模型时钟 `elapsed_minutes` 改回 Leader 定下的口径（即用 `elapsed_end_s_DIAGNOSTIC / 60.0`）；


2. 生存公式里的步长 `delta_minutes` 改为**固定单位步长**（例如常数 `1.0` 分钟，物理意义清晰：给定当前已耗时间 $e_t$，用户再多活 1 分钟/下一屏的条件概率），而把当屏视频物理片长 `slate_durations` 留在特征向量 `x` 里交给网络自己学权重即可。

### 5. 补充提醒：看实验结果时，盯死 `User-GAUC` 和 `LogLoss`

ChatGPT 在 `README.md` 里写了一句非常关键的大实话：

> *“该标签只有每场末屏为 0，因而无需训练的 `-req_idx` 就能在所有 eligible 会话上取得 `Session-GAUC = 1`。”*
> 
> 

因为在**单场 Session 内部**，标签序列永远是 `[1, 1, ..., 1, 0]`，时间 $e_t$ 和屏号 `req_idx` 永远单调递增，所以任何随时间单调递减的函数在单场内的 `Session-GAUC` 都是满分 `1.0`。
因此，跑完后看结果时：

* **不要看 `Session-GAUC**`（没有区分度）；


* **核心看 `User-GAUC**`（把同一个用户在不同日期、不同长短的多个 Session 混在一起排序——此时短 Session 的第 2 屏是 `0`，长 Session 的第 5 屏是 `1`，单靠 `-req_idx` 就会排错，必须靠预算先验 + 内容塔协同才能排对）以及 **`LogLoss` / `Pooled-AUC**`。



你可以把上面这 **4 处修改指令（① 测试用户用自身历史过去场算先验；② `content_net` 偏置初始化为 $+2.0$ 且 `stage 2` 对 `budget_net` 输入做 `detach`；③ `budget_net` 参数网络内部掩码掉时钟 `B2`；④ `elapsed` 改用 `elapsed_end_s` 且 `delta` 设为常数 `1.0`）** 直接发给写代码的 Agent 让它修好重跑一版，跑出来的指标就会非常扎实了。



基于 `20261116_kr-time-budget-argon-report.md` 的审计结果，当前实验暴露出两个核心问题：
1. **严重的 Multi-Epoch Item-ID 过拟合**：包含 `slate_items` / `history_items` 的三个模型（Content / Fusion / Ours）在跑满 8 epochs（且 Embedding 零衰减、无 Dropout）后，测试集 LogLoss 劣化至 0.76~1.05（远差于常数基线的 0.2367），而屏蔽了 item/tag 序列的 Budget-only LogLoss 为 0.2472、User-GAUC 达 0.5532。
2. **双塔耦合与先验失配**：测试用户被填入了全局常数预算先验；`budget_net` 输入中混入了会话内时钟 B2 导致 39.52% 相邻步 `log S` 上升；Stage 2 切换时未初始化 `content_net` 偏置且未隔离共享层梯度，引发梯度休克。

请新建 `v2` 实验配置与输出目录，按以下 6 条规则修改代码并重跑对比：

### 1. 解决过拟合与训练轮数（对齐 KR 单 Epoch 规律）
- **序列高基数 ID 治理**：在 6.1 退出预测筛查阶段，提供两套明确对照（或默认屏蔽纯 `item_id` Embedding，仅保留低基数的 `tag` Embedding + 训练集贝叶斯平滑后的物品历史质量先验 `B4` 稠密特征）；若保留 `item_id`，必须将截断频次从 `<5` 提高到 `<50`，并对 Embedding 施加 `weight_decay=1e-5` 及 `Dropout(0.2)`。
- **Epoch 与验证早停**：KR 数据集单 Epoch 即可收敛。从每折训练用户中切出 10% 用户作为 `valid` 集，最大训练轮数设为 `3 epochs`（或按 valid LogLoss / User-GAUC 选最优 checkpoint，并在每个 epoch 的 0.25/0.5/1.0 处评估 valid），消除第 8 epoch 的严重过拟合。

### 2. 修复测试用户预算先验的分布失配（`build_requests`）
- 当前 `GroupKFold` 下测试折用户全部为未见用户，给测试用户统一填充训练集总体常数先验会导致测试时该特征方差为 0。
- **修改**：无论是训练用户还是测试用户，计算 `user_hist_session_s` 等历史已完成会话统计量时，统一使用**该用户自己在当前请求日期之前（严格过去已完成会话）**的历史记录，并用该折训练集的全局先验做贝叶斯平滑（例如伪计数 `m=5` 场）处理冷启动。

### 3. 修复预算生存塔的参数可识别性（`time_budget.py`）
- **特征路由**：在 `mixture_survival(self.budget_net(x_budget), elapsed, delta)` 中，输入给参数网络 `budget_net` 的向量 `x_budget` 必须**掩码置零会话内时钟特征 `B2`（如 `elapsed_minutes`, `req_idx`）以及当屏特征 `B4`**，使混合威布尔参数 $(\pi_k, \lambda_k, z_k)$ 在同一场会话开始时（或仅随前序历史状态）保持稳定，而会话内时间流逝严格只通过生存公式自变量 `elapsed` 起作用。これにより、相邻步 `log S` 严格单调递减，同时利用 2 分量混合威布尔的后验转移自然刻画跨会话的幸存者效应（驼峰风险）。

### 4. 对齐物理时钟与固定步长 `delta`
- 将生存公式的 `elapsed_minutes` 切换为 Leader 指定的挂钟口径（即 `elapsed_end_s_DIAGNOSTIC / 60.0`）。
- 生存公式中的 `delta` 不再使用当屏 6 个视频的物理总片长 `slate_dur_sum_s`（避免长视频片长直接拉低 $\gamma$ 造成混杂），改为固定单位步长 `delta = 1.0`（分钟）或训练集单屏中位耗时常数；当屏物理片长保留在 `B4` 特征向量中供网络学习。

### 5. 消除 Stage 2 切换时的梯度休克（`Ours` 模式）
- **偏置初始化**：将 `self.content_net` 最后一层 `nn.Linear(32, 1)` 的 `bias` 初始化为 `+2.6`（对应 $\text{sigmoid}(2.6) \approx 0.93$，对齐全集留存基准率），避免从 Stage 1 切换到 Stage 2 乘积时预测值突然减半引发梯度爆炸。
- **梯度隔离**：Stage 1（前 1 个 epoch）仅用 `gamma` 训练 `budget_net` 及其关联编码器；Stage 2 训练 `gamma * stay` 时，对 `gamma` 分支做 `gamma.detach()`（或完全冻结 `budget_net`），让 `content_net` 在锁定的时间预算基准上专门拟合内容残差。

### 6. 指标与诊断输出
- 汇报 `User-GAUC`、`Pooled-AUC`、`LogLoss`，并增加一个 **`Intra-Step GAUC`（按 `req_idx` 分桶或 `(user_active_degree, req_idx_bin)` 分组计算的 GAUC）**，用于在固定会话进度（消除 `±req_idx` 幸存者偏置）下，纯粹检验模型区分“继续 vs 退出”的能力。
