# 开放课题自主探索

## 适用场景

用户给出一个研究课题、机制假设或大方向，希望 agent 自主拆解、设计实验、跑结果、判断正负信号。

## 先读什么

- 最近交接：`research/handoffs/`
- 方案文档：`research/plans/`
- 经验总结：`research/findings/`
- 参数和实验：`docs/rosen/PARAMS_AND_EXPERIMENTS.md`
- 训练流：`docs/rosen/TRAINING_FLOW.md`
- 涉及新模型时读 `docs/rosen/request_execution/03_new_model_experiment.md`
- 涉及新数据时读 `docs/rosen/request_execution/02_new_dataset_preparation.md`

## 边界约束

- 不要把一次偶然 partial AUC 叫正信号。
- 不要在没有 baseline 或对照口径不清的情况下判断有效。
- 不要同时改变多个关键变量，除非明确是在做探索性 sweep。
- 不要只跑轻量 obs 就给强结论。
- 长实验和后台任务必须可观察。

## 需要做的事情

### 读取历史和理解课题

开放探索开始前先考古：最近交接、同课题方案、历史实验结果、已知失败原因。不要重复做已经证明无效的实验。

理解课题时要把用户的想法转成可实验的假设：它想改变什么机制，应该影响什么指标，最小对照是什么。

### 设计实验路线

实验路线不必一开始很复杂，但需要有 baseline、单变量变化和可解释对照。必要时可以先做 smoke 或轻量 obs，但要明确它们只能帮助排查方向，不能直接给强结论。

如果课题涉及新模型或新数据，应回到对应需求文档处理，不要把所有事情混在一个探索脚本里。

### 执行和持续观察

实验运行要有清楚命名、日志路径和可恢复的命令。记录长任务进度，确保用户随时能知道当前是在训练、评估、数据准备还是排队。

过程中如果用户询问进度，应优先给高信号信息：当前任务、step/s、资源占用、已有指标是否 partial、预计下一步。

### 判断信号

判断正负信号时要回到对照关系，而不是只看单个 AUC。需要区分 full/partial、valid/test、student/EMA、不同 seed、不同数据切分。

如果证据不足，应明确说“不确定”，并给下一步最小实验，而不是硬下结论。

### 沉淀结论

开放课题通常会跨多轮对话和多次实验。阶段性结论、失败实验和下一步计划应写到 `research/`，让后续 agent 能接上。

## 文档写回要求

开放探索必须留下人类可读记录：

- 课题假设。
- 实验集合和路径。
- 关键指标。
- 结论等级：正信号、负信号、不确定、无效。
- 下一步建议。

## 完成标准

- 至少有 baseline 和一个可解释对照。
- 用户能区分“已经证实”和“只是观察到”。
- 后续 agent 能根据文档继续，不必重新考古。
